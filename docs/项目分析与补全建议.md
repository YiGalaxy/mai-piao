# 项目分析与补全建议

## 项目定位

麦票是一个 Java 21 / Spring Boot 3 的微服务售票学习项目，覆盖影片和演出浏览、场次排期、座位锁定、下单、支付、退款、抢购准入及管理后台。它的重点不是内容管理本身，而是有限库存下的并发控制、分布式状态迁移和失败恢复。

目前项目已超出基础脚手架阶段：模块可以编译，两个 Vue 前端都能产出生产构建，订单、支付、座位和抢购关键路径有自动化测试。此结论只说明代码构建和已有测试通过，不等同于 Compose 全栈启动、数据库初始化、支付端到端或生产容量已验收。

## 架构与业务链路

| 模块 | 职责 |
| --- | --- |
| `maipiao-gateway` | 统一 HTTP 入口、JWT 和角色校验、路由及抢购请求拦截 |
| `maipiao-user` | 用户、登录、角色、优惠券 |
| `maipiao-movie` | 影片、场馆、场次、票档、座位账本及运营接口 |
| `maipiao-seat` | Redis 座位状态、原子锁座/释放与座位图 |
| `maipiao-order` | 订单状态机、预约协调、取消、超时及退款请求派发 |
| `maipiao-pay` | 支付、通知幂等、退款及支付/座位补偿任务 |
| `maipiao-queue` | 抢购排队、准入令牌和管理操作 |
| `maipiao-mock-pay` | 模拟收银台及可重复、延迟和异常回调 |
| `common-*` | 公共结果/异常、Redis 辅助能力及管理员审计 |

典型购票链路为：查询场次和座位 → Redis Lua 原子锁座 → Seata AT 事务内创建订单并扣减库存/锁定优惠券 → 创建模拟支付 → 支付回调幂等推进订单并出票 → Redis 确认售出。取消、退款和回调失败由补偿任务处理。Redis 状态与关系型数据库分开，因此最终正确性依赖显式补偿和定期核对，而不是单一事务覆盖所有系统。

## 当前完成度与边界

- **已实现**：多模块 Maven 后端、Spring Cloud Gateway / Nacos、MySQL 多 schema、Redis 座位控制、Seata AT、RocketMQ 订单超时消息、支付/退款补偿、用户端和管理端、演示支付、数据库 schema 与 demo SQL。
- **有测试覆盖**：下单与预约、取消/支付状态推进、退款派发、座位运行逻辑、支付创建/可靠性/座位同步、抢购准入、管理员审计、模拟支付存储。
- **仍需真实环境验收**：空数据卷初始化和全部服务启动、网关到各服务的完整浏览器购票链路、真实 Redis/MySQL/RocketMQ/Seata 下的跨服务事务、支付回调乱序/重复与退款端到端、故障重启后的补偿收敛。
- **明确不代表生产就绪**：支付渠道是 mock；当前压测聚焦排队、锁座和售罄拒绝，不是生产容量结论；项目文档也列明实名跨订单累计限购、完整自动对账等边界。

## 本次验证

- `mvn -B -ntp test`：12 个 Maven reactor 模块均成功。已有测试未发现失败；预约基础设施测试 8 项和支付基础设施测试 4 项按测试条件跳过。
- `maipiao-web` 的 `npm run build`：成功。
- `maipiao-admin-web` 的 `npm run build`：成功。
- 两个前端构建均报告约 1 MB 的主 JavaScript chunk，超过 Vite 默认 500 kB 提示阈值；这是优化项，不影响本次构建成功。
- 本轮未启动 Docker Compose，因此没有把基础设施或浏览器端到端运行描述为已验证。

## 建议补全顺序

1. **建立可重复的全栈验收**：用独立 Compose 项目名和数据卷启动空环境，自动应用 schema/demo SQL，健康检查所有服务，并执行登录、锁座、下单、模拟支付、出票及取消的 API 流程。
2. **补齐关键服务测试空白**：gateway JWT/路由规则、用户注册登录授权、movie 排期和库存写入目前缺少与订单/支付同等的服务级测试。优先覆盖权限边界、非法时间/数量、重复请求和并发条件更新。
3. **演练跨存储失败恢复**：在订单提交、支付通知、退款和 Redis 座位确认的关键边界注入超时/进程重启，验证重复执行安全、补偿最终收敛，并留下可重复脚本和结果。
4. **处理前端产物体积**：检查 Element Plus 全量导入和图标引入，按需导入组件并配置合理的 vendor 分块；以构建体积与页面加载测量结果决定是否继续拆页面。
5. **统一数据库迁移管理**：当前已有库升级靠人工按文档执行 SQL，部分 DDL 不能整文件重跑。后续将迁移接入 Flyway/Liquibase，并为旧库升级提供版本记录和测试。

## 文档注意事项

`README.md` 是当前运行入口；`docs/设计方案.md`、`docs/历史规划.md` 等文档包含规划和历史取舍，不应把其中的 Sentinel、Canvas、服务端数量或目标压测指标直接当成现状。演示数据接口要求 `dev` profile、显式 `MAIPIAO_DEMO_ENABLED=true`，并经网关携带管理员 token 调用。
